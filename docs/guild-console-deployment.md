### 微信网页扫码登录

网页端登录使用微信开放平台的“网站应用”，不是小程序 AppID 或微信支付 AppID。上线前需要：

1. 在微信开放平台创建/启用网站应用，将网站授权回调域配置为正式 HTTPS 域名（例如 `dlmclub.com`）；本系统实际回调地址为 `https://dlmclub.com/api/auth/callback/wechat`。
2. 将该网站应用和当前小程序绑定到同一个微信开放平台主体/账号体系，以便两端登录返回相同的 `unionid`。
3. 在 Web 服务设置 `WECHAT_WEB_APP_ID` 和 `WECHAT_WEB_APP_SECRET`，并保留正确的 `SITE_ORIGIN`。

系统只在首次网页登录拿到 `unionid` 时才会创建或关联 DLM 账户：已有小程序账户会自动复用余额、订单和资料；若微信没有返回 `unionid`，页面会停止登录并提示配置问题，绝不会新建一个余额分离的账户。Bot 不需要这两个密钥，但 Web 与 Bot 都必须更新 Prisma Client，以识别新增的 `WECHAT_WEB` 身份提供方。

## 订单审计与特殊券协议更新

新增 `20261022040000_order_audit_applied_effects` 记录订单实际收入／充值拆分、累计流水、心动与返佣唯一流水凭证。两仓文件一致，当前未执行。新结算仅在权益和审计全部成功时写 v2；旧 v1/NULL 不自动回填。撤销仍按原凭证和当前实际归属处理；2026-10-24 已允许按原额扣回相关余额、积分、累计消费、陪玩流水及心动，数额不足可形成负数，不再因这些数值不足拒绝。归属不明、历史凭证缺失、实际差值不符及缺唯一优惠返利流水的已用折扣订单仍停止，不能通过改 v2 标记解锁。额度恢复保留原期限，过期不恢复。

系统自动结单已统一标记来源，不增加陪玩累计流水、不消耗双倍流水额度；正常收入、老板消费、积分、心动和原自动权益规则保留。审计记录实际零累计，撤销不扣未获得的流水。旧单仅缺固定 `hostDlmId` 时已按第 16 项恢复使用当前 Discord 绑定，锁定本次选择并在结账时保存实际付款账户；原已保存身份仍须核对。

特殊券请求必须包含服务器根据已验证登录与目标解析生成的 `userDlmId/userId`，定向券还需 `targetDlmId/targetDiscordId`；陪玩考核还核实 `peiwanId`。Bot 在同一事务锁定并重验这些身份后才消费和发放，缺断言或绑定变化返回 409，不从旧 Discord 补建账户。该协议与旧 Web 不兼容，需协调发布并检查全部内部调用方。前端只保存目标字符串时，Web 收到请求前已发生的身份复用仍需要目标确认界面解决；礼物分支已在后续整合增加固定 giver/receiver DLM、Discord 及陪玩 ID 校验，详见下面更新。

Web 直接自用券在同一事务锁后重验登录身份再条件消费。特殊券和改名卡内部请求遇到超时、连接丢失、5xx 或不可解析成功时只请求一次，提示先核对券状态和权益、勿重复提交；这不等于已有持久化请求幂等回执，重新提交未固定券 ID 的请求仍可能选另一张券。

新迁移必须先经审查和授权执行。回退旧 Bot 会停止写完整订单事实，回退旧 Web 会让特殊券请求因缺身份断言被拒绝；回退不能删除已有事实或恢复批次。订单仍保留 Order→钱包闸门，身份迁移存在反向路径，真实数据库死锁、触发器及进程恢复尚待验证。

2. 将 Web 和 Bot 的内部通知密钥与 URL 配对，再部署两端。
3. 配置微信开放平台和上述两个网页登录环境变量；用已有小程序老板扫码，确认进入同一份余额和订单，再用未绑定 Discord 的微信账号验证可进入 `/console`。
4. 用获授权的测试老板和陪玩，完整验证创建订单、陪玩接受、老板取消和人工余额入账。Stripe 充值按下述现行状态与入账规则，在获授权的隔离环境验证；退款／争议发生在到账后的余额处置尚无自动闭环。
